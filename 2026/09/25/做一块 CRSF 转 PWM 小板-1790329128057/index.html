做一块 CRSF 转 PWM 小板

我想做一块小板，把 ELRS 接收机的 CRSF 串口数据转成舵机、电调能用的 PWM 信号。接收机负责无线通信，小板负责解包和输出.

单看功能，这个工程确实不大。真正需要花时间的地方，藏在几个看起来已经解决的问题里：串口能收到数据，还得知道从哪里开始算一帧；通道值能变成脉宽，还得考虑失联以后继续输出什么。这次整理时，完整程序能在一套配置下编译通过，换成目标芯片的容量限制，却连链接都过不了。

其中 crsf2pwm.ino 和 CrsfSerial.cpp 是主线。前者决定收到通道值以后做什么，后者负责把通道值从串口里取出来。

CRSF 解析：先从字节流中找到完整的一帧

工程里的 CRSF 串口设为 420000 baud，接收机端需要使用匹配的配置。

普通 CRSF 帧在本项目中的布局是：

长度字段只统计它后面的内容：一个类型字节、N 个数据字节，再加一个 CRC。因此 长度 = N + 2，整帧是 N + 4 字节。CRC 从类型开始算，覆盖到 Payload 末尾，多项式为 0xD5。协议原文 TBS 的帧格式说明。

格式本身不难，麻烦在于 UART 只管送字节。假设接收机已经在发数据，MCU 这时才启动，读到的第一个字节完全可能落在 Payload 中间。直接把它当帧头，后面的长度和类型就全错了。

所以 handleByteReceived() 会一边收，一边尝试找边界。缓冲区里至少有两个字节时，先把第二个字节当作候选长度；长度不在 3～62 之间，就扔掉最前面的一个字节，再试一次。

要等到缓冲区凑够 长度 + 2 字节，再计算 CRC。校验通过才处理整帧并把它移走；校验失败，同样只移动一个字节，继续找。

如果收到一半就没动静了，超过 100 ms 没有新字节，程序会清掉残留数据，避免一直守着一个凑不齐的包。

普通 0x16 通道帧需要 22 字节通道数据，而代码识别到类型后，就直接按结构体读取了。CRC 正确只说明校验值对得上，不能保证 Payload 足够长；一个过短但 CRC 正确的帧，仍可能让解析器读到缓冲区里的旧内容。后续要在帧分发之前，按类型再检查一次长度。

失控保护

如果最后收到的命令是加油门，之后串口断了，总不能一直照着最后一个数输出。这也是为什么失控处理要跟着通道解析一起看。

代码用 _lastChannelsPacket 记住最近一次通道帧的时间。连接建立后，超过 300 ms 没有新通道帧，就触发失控回调。其他类型的帧不会刷新这个时间戳，串口上还有字节也没用，得有新的通道数据才算。

默认失控配置为：

输出通道 失控动作
1 输出 1500 µs
2 输出 1500 µs
3 输出 988 µs
4 输出 1500 µs
5～7 保持最后一次脉宽
8 停止脉冲

固定值比较直观，就是主动给设备一个位置或油门指令。fsaHold 则什么也不改，让 PWM 继续保持最后的脉宽。停止脉冲走的是另一条路径：调用 pwm_stop()，再把引脚改成下拉输入。

固件等第一帧通道数据来了，才初始化 PWM，这样不会在启动时先发出一组随手设定的值。不过，失控回调只会在已经建立过连接之后触发。如果上电以后始终收不到数据，程序走的并不是“连接后失联”那条路径，这两种情况要分开测。

接收机的行为也会影响结果。假如无线已经断了，接收机却还在不断发送保持值通道帧，转接板就会觉得数据仍在更新。后续实测时，关闭遥控器、给接收机断电、拔掉串口线，再重新连接，都需要试一遍，才能知道两边的失控设置是否配合。

电压回传

电压回传走的是“分压 → ADC → 滤波 → 换算 → CRSF 打包”这条路径。
